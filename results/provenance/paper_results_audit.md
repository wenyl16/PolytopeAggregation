## Recommended removal candidates

- Entire `results/aggregation/T24/lambda_sensitivity` and its unique runner/tester/drawer/summarizer, plus `figures_summary/08_lambda_sensitivity*`. The paper discusses weighting conceptually but contains no numerical lambda sweep, figure, table, or quoted sweep values. The one/two/three-stage experiment is separate and must stay.
- `results/aggregation/T24/training_budget_comparison/pb`: the current drawer already has `TEMPLATES = ("peb",)`, and the PDF describes only PEB. Root shared metadata currently contains PB records; it can remain as original provenance or be carefully pruned without altering PEB arrays.
- `results/microgrid/taheri2022/run_20261028_budget1000` and `...retry1`: setup/earlier attempts, not the cited final retry2. Readable retry2 JSON has no references to these folders; retain retry2 fully.
- Runtime/editor caches and project IDE directories (`__pycache__`, `.pyc`, `.idea`, `.vscode`) are not research evidence.
- Nonconvexity `example_ESS400_check*`, old illustrative `example_recheck*` and storage-diagnostic extra experiments are not cited final Table IV values. However keep any file referenced by a retained checkpoint/hash verification or required source dependency; blanket deletion based on a generic name would be unsafe.
- Old PDFs and previews outside the supplied target figures, if not necessary to any paper result, can be removed after the supplied PDFs and table outputs are centralized. Preserve all numeric sources and logs that explain actual training/test runs.

## Provenance and consistency issues that cleanup must not silently rewrite

1. **Author-supplied gradient runtimes.** PDF reports 197.2 s vs 195.6 s, difference 1.621 s / .83%. `tmp/gradient_runtime_and_baseline_budget/manifest.json` records these explicitly as `author_supplied_training_times` (197.215 and 195.594), `not_a_new_experiment=true`. Current ten-seed saved summary reports 228.3352778304 vs 226.1971799503 s; current per-step logs are real saved evidence but do not reproduce the author-supplied timing. Preserve an explicit provenance excerpt with the manuscript numbers and distinguish measured saved records.
2. **Gradient evaluation sample count.** PDF says 5000, while figure data pipeline/current retained cohort includes `evaluation_10000_seed10000` and bootstrap over 10000. Retain both existing evaluation-level datasets, prefix verification, figure source_data and actual input hashes; do not claim a new 5000-direction recomputation was performed.
3. **Budget iterations and runtimes.** PDF says 1000/2000 updates and 197.2/390.7 s. Current PEB configs contain 1003/2006 updates and 225.7675913001/461.01739399997 s; existing drawer validates these actual counts and only caps displayed x at 2000. No raw source for 390.7 was located in this read-only audit. Preserve actual histories/configs and state this mismatch.
4. **T96 update count.** Paper broadly invokes Table I stage schedule, whereas saved T96 run has 301/201/501 = 1003 updates; the table timing/errors otherwise match precisely.
5. **Old microgrid figure provenance.** `figures_original/README.md` describes conservativeness .02 but current microgrid training config and paper use .05. The supplied PDF must be kept byte-for-byte even if it predates current underlying model. Do not redraw automatically as part of cleanup.
6. **Repeated runtime ranges.** Paper states seven-device training varied about 200–1500 s and 21-device exceeded 7000 s. The active latest summaries support 980.61/2843.94 only; previous logs producing those range extrema were not identified here. Keep surviving historical scale3 snapshots/provenance that may explain repeated tests, and label unavailable per-run evidence rather than fabricating it.
7. Table IV data uses the retained historical model snapshot; its summary notes HP first-step temperature indexing is as originally implemented. Retaining runtime source snapshots is necessary for reproducing these numbers, even where current model code differs.

Figures 1–3 are conceptual/algorithmic illustrations. No corresponding numerical simulation family under the three audited directories was identified. Their mathematical examples do not justify deleting any current dependency used by the required experiment families above.
